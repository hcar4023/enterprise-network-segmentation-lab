# Enterprise Network Segmentation & SSH Security Monitoring Lab

A hands-on cybersecurity engineering lab focused on designing, implementing, and validating network segmentation, firewall access controls, secure remote administration, and Linux authentication monitoring.

## Project Overview

This project simulates a small enterprise-style network using Oracle VirtualBox, OPNsense, Kali Linux, and Ubuntu Server.

The lab separates an administrative testing network from a protected server network using distinct VirtualBox internal networks and OPNsense firewall policies.

The primary objective is to demonstrate how restrictive network access controls, SSH hardening, and security log analysis work together to improve infrastructure security.

              |                         |
              +---- TCP/22 SSH ---------+
                   Explicitly Allowed

        Other tested IPv4 traffic between

The lab uses two isolated VirtualBox internal networks rather than physical VLANs.

## Implemented Security Controls

### Network Segmentation

- Created separate attack and server network segments.
- Configured OPNsense to route and filter traffic between segments.
- Implemented a narrowly scoped rule allowing SSH from the Kali workstation to Ubuntu Server.
- Implemented a broader IPv4 blocking rule between the attack and server networks.
- Disabled the broad default LAN IPv4 allow rule.

### SSH Hardening

- Configured Ed25519 public-key authentication.
- Disabled SSH password authentication.
- Disabled keyboard-interactive authentication.
- Disabled direct root SSH login.
- Disabled X11 forwarding.
- Limited SSH authentication attempts through `MaxAuthTries`.

### SSH Security Monitoring

- Generated a controlled SSH connection using a nonexistent username.
- Identified the resulting `Invalid user` event in Ubuntu's SSH journal.
- Distinguished the invalid-user event from the related pre-authentication connection closure.
- Developed command-line filtering techniques using `journalctl`, `grep`, and `awk`.
- Extracted event timestamps, attempted usernames, source IP addresses, and source ports.

## Verified Security Testing

| Test | Observed Result |
|---|---|
| Kali to Ubuntu ICMP | 4 packets transmitted; 0 received |
| Kali to Ubuntu TCP/22 | Open; SSH connection permitted |
| Valid Ed25519 SSH authentication | Successful |
| Password-only SSH authentication | Denied |
| Controlled invalid-username SSH attempt | Logged as `Invalid user` |
| Precise invalid-user event count | 1 event in the tested journal window |
| Security log field extraction | Timestamp, username, source IP, and source port successfully extracted |

## Limitations and Future Work

- IPv6 segmentation has not yet been fully validated.
- A temporary external ICMP test rule requires a final configuration audit.
- VirtualBox performance limitations and intermittent Ubuntu guest soft lockups remain under observation.
- The custom SIEM project is planned separately and has not yet been integrated into this lab.

## Project Development

The project follows an evidence-driven engineering methodology:

**Configure → Test → Observe → Analyze → Document**

Firewall behavior, authentication controls, and detection logic are documented according to observed results rather than assumed outcomes.

## Next Phase
